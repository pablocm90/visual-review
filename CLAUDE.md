# visual-review

Structural review pages for pull requests, ranges and uncommitted work: the Rust crates and modules, the TS/JS modules and the Rails classes of a repo, before and after, with what changed coloured, and optional notes written by Claude or anyone else. Being made public as `@pablocm90/visual-review`.

## Where things are

The layout: `src/core/` holds the ports (`Reader`, `Linker`), config, `read-range.ts` and `read-stacks.ts`, the diff, the collapse rules (`visible-diff.ts`: what is drawn at an expansion, its unchanged edges merged per pair of boxes unless the page's "All edges" is ticked, what the page's Show keeps of it, `changesOnly` (the default: changed nodes and the ends of added or removed edges) `logicOnly` (the files with a changed decision, boxes open, every edge between them, whatever `expanded` and `drawn` say), or `nearChanges` (one hop of any edge touching a change), or, on a PR's later round, `sinceLastReview` (what changed since its last review, at the expansion drawn), and what going to an id opens, widening Show as far as it needs) and notes, placed on them (`notes.ts`); the adapters sit behind the ports in `src/readers/{rust,typescript,rails}/` and `src/linkers/fetch-axum/`, listed in `src/adapters.ts`, which `cli.ts` hands to `readRange` (the core imports neither it nor `on-path.ts`); `src/git/` holds the git, `gh` and `PATH` plumbing; `src/viewer/` is the page, which imports the core and never the reverse. Bare file names below live in those folders.


- A lockfile changed in the range becomes `PageData.dependencyChanges`, read by `readLockfiles` (`read-lockfiles.ts`, a `readRange` option beside `Adapters`, since `readStacks` never uses them) through each `Lockfile` port (`lockfile.ts`) in `src/lockfiles/{pnpm,npm,yarn,cargo,bundler}.ts`, listed in `adapters.ts`; they aren't `Reader` methods because a lockfile needs no drawn stack, a gem no Rails root. `git show` reads each side's text at its commit, so a symlink reads as its link text, and `\r\n` is normalised once there. Lockfiles of one ecosystem in one folder that changed together are read as one, so moving package manager raises only what moved, and a rename goes by its last path. A reader fails closed: any line its tool wouldn't have written throws, which raises "not read" naming only the format, since a quieter reading could hide a package. `yarn.lock` alone takes `Lockfile.manifest`, each side's `package.json` files under its folder. `packageChanges` (`dependency-changes.ts`) pairs the sides by compatibility line, and `dependency-findings.ts` raises the findings, each with `Finding.file`, which the rail, Start here and the tray open through `showFile` in `review-page.tsx`: the node holding the file in its Full diff, else the files outside the graph, landing at the patch's top.
- A Rails migration the range adds becomes `PageData.migrations`, read by `readMigrations` (`read-migrations.ts`, a `readRange` option beside `lockfiles`) through each `MigrationReader` port (`migration.ts`), so no drawn stack is needed and `Reader` stays as it is. `railsMigrations` (`readers/rails/migration-risks.ts`, listed in `adapters.ts`) holds the paths Rails would run and gives each risk's title, why and line, reading every call except under `def down`, `def self.down` and a `down` block; a table the file creates raises no index or `null: false` risk, a reference indexes unless its `index:` is `false`, `nil` or concurrent, a `change_table` column only with `index:` (`add_column` takes none: ActiveRecord refuses the key), and a file that doesn't parse throws, kept as `notRead`. A path counts when it's absent at the base, so a rename counts and an edit doesn't, unless it moves a migration with its version kept (`MigrationReader.version`): that one has already run. `migration-findings.ts` raises one `schema` finding to look at per risk, with `Finding.file`, so the page opens it through `showFile` as it does a lockfile; only `schema:not-read:` is a blind spot in Start here.
- A schema dump the range changes becomes `PageData.schemas`, read by `readSchemas` (`read-schemas.ts`, a `readRange` option beside `migrations`) through each `SchemaReader` port (`schema.ts`), so no drawn stack is needed. `railsSchema` (`readers/rails/schema-tables.ts`, listed in `adapters.ts`) holds `db/schema.rb` and `db/<name>_schema.rb` outside `NOT_SEARCHED` and reads each `create_table`, a column being any `t.<word>` that isn't an index or a constraint, every option kept as one as-written string; a file that doesn't parse throws, kept as `notRead`, and a dump absent at one side reads as `whole`, with its table count, so moving to `structure.sql` raises no table. `diffTables` (`schema-diff.ts`) pairs tables, columns and indexes by name, and `schema-findings.ts` raises the findings, each with `Finding.file` and, when it's about one table, `Finding.table`. `showFile` sends a file in `review.schemas` to the Schema tab (`schema-screen.tsx`, `SchemaLanding` focusing the card or the file's section); the tab is absent, and `#schema` falls back to Structure, with no schema change.
- A route change becomes `PageData.routes`, read by `readRoutes` (`read-routes.ts`, a `readRange` option beside `schemas`) through each `RouteReader` port (`routes.ts`), since a route file can't be read alone: `load` and `draw` join them, and `draw` under a `namespace` takes its prefix. When a held path changed, both sides' held files come through `git show`, so an unchanged file a renamed namespace reaches still counts. `railsRoutes` (`readers/rails/route-reader.ts`, listed in `adapters.ts`) expands them over tree-sitter-ruby with `inflection.ts`, ActiveSupport's table, which `rails-graph.ts` shares; a root is a `config/routes.rb`, a file nothing reaches isn't read as routes, and what it can't expand without guessing is `unread`, by source text and line, with what sits under it. A reading stops at `MOST_SPENT`, since repeated draws and nested names multiply, and that or a parse error throws, kept as `notRead`: its `file` is the changed file a `RouteFileNotRead` (a parse error or too big) names, else, as for that limit or an unchanged file, the first that changed. `diffRoutes` (`route-diff.ts`) keys routes by root, verb and path, the first drawn answering, and compares `unread` as a multiset by root, path, module and text. `route-lines.ts` reads PATCH and PUT of one path and target as one line, and `route-findings.ts` raises the `routes` findings, each with `Finding.file`, the row's `patch`, and, for one route or statement not read, `Finding.route`, its key in `route-lines.ts` (`lineKey`, `keyedStatements`, the text counted); only `routes:not-read` is a blind spot in Start here. `showFile` sends a `patch` the reading holds to the Routes tab (`routes-screen.tsx`, `RoutesLanding` focusing the row, the statement or the file's section), the rail and the tray passing `table ?? route` as its place; each file's section has `Show patch`, through `showPatch`, the part of `showFile` that opens a file's patch on its holder's Full diff or in the files outside the graph; its rows share `change-row.tsx` with Schema, and the tab is absent, `#routes` falling back to Structure, with no route change.
- `src/viewer/` is the page: React + ELK, built by vite with `vite-plugin-singlefile` into one file, `dist/viewer.html`. `review-page.tsx` holds the tabs (Structure, Tests and, with a schema change, Schema, and with a route change, Routes, picked by the URL's hash; the selection is its state, so it holds across tabs) and the Structure screen: the findings rail on the left (`findings-rail.tsx`: skipped stacks, then the findings grouped by dimension, each going to its target or opening the changed files outside the graph), the lens chips (`LensChips`, five chips over `lenses.ts`'s `LENS_OF`, the viewer's own grouping of the dimensions, each filtering the rail and Start here and dimming other badges, and naming what it checked, "dependencies checked, nothing found", with no findings and nothing unread; `LensRow` under them lists the picked lens's dimensions from `PageData.coverage`) and Start here above the graph (`StartHere`: each line names its lens and dimension; a line of one goes as the rail's finding does, a line of several opens in place to list them, a split's line opens the rail; first, with no lens or Behaviour picked, a line that is no finding, `logicTotalsOf`'s (`logic-strip.ts`) count of the range's changed decisions, going to Show's Logic only), one findings badge per drawn node or edge, the graph, coloured by change, churn, complexity, kind of change or, with a changed decision, logic (`colour-by.tsx`; a box takes the strongest kind inside it, a changed node with none reads "symbols not read", and the sum of the decisions changed inside it), and the inspector on the right, its head (`InspectorHead`: name, state, Comment, Mark read, Next; `C` asks through `CommentAsked`, a context in `comment-field.tsx`, cleared when the selection changes, for the focused logic row when one is (`data-comment-anchor`), else for the part), then Note (`NotePanel`, the reading column: the note, `WhatChanged` (`what-changed.tsx`, below), Why look, the part's findings with their answers, and Tested by (`TestedBy`, `tests-screen.tsx`), its `tests:untested-logic` finding with its answers, then its test files through `useTestsToRead`, cut to the changed tests and the unchanged ones holding a draft or a last comment or changed since (ids anchored before the cut), both finding lists sharing `FindingRows` (`finding-rows.tsx`), opening at its top on a new part; `LandedRows` outlines the row gone to, a finding's by `goToFinding` from the rail and Start here, which leave focus and tab as they are, or `goToDraft` from the tray and the last review's list (`whereOf`), which focuses it; an edge has no What changed, and "No note" shows only when the column holds nothing else, a file whose symbols are all unchanged holding nothing), then two closed folds (`Fold`), Metrics (`metrics-tab.tsx`: base and head side by side, each function's cyclomatic paired across the sides), and Full diff (on a served page a numbered patch line takes a comment through `CommentOn`, here and in the files outside the graph, anchored by `lineAnchor`, its place read back by `placeOfLine`; a patch opens by itself when it holds a draft or the landing, the row `useLanding` keeps until the selection or the panel changes). What changed (`what-changed.tsx`, its count and `logicTotalsOf`'s sum in its heading, `LogicLegend` (`logic-strip.tsx`, above the graph on Logic only too) under it when a strip shows: a file's symbols grouped by change, a changed signature line by line with its members as they were folded (`signature-lines.tsx`), an edited function's logic under it as a strip (`LogicStrip`, `logic-strip.tsx`: a tick per `LogicLine`, a button at `tabIndex` -1 going to its row by the page's landing, so a draft on a decision rings it too, and its counts, from `src/core/logic-strip.ts`) over its rows, or a box's files with theirs; the rows are a `<details>`, open when the file holds at most 8 changed decisions (`holdsFewChanges`) or a row holds a draft, a last comment or a changed-since mark, and each run of unchanged rows (`runsOf`) a nested one, opening whole on the same news so no row moves and remounts its comment field, `LandedRows` opening every fold around a row; a logic line that changed opens Full diff on its file's patch, at its row by the line numbers `highlightPatch` reads from the hunk headers, else at the patch's top; on a served page a symbol row and a logic line each take a comment through `CommentOn`, a logic line's anchor from `decisionsOf` in `symbol-findings.ts`, which its `logic:removed` finding's id comes from too; a draft on either, or on a test, goes to its row, `holdsRow` saying the page still holds it, else to the graph node; a non-quiet row's `Diff` toggle, `SymbolRow`, opens `symbol-lines.tsx`: `rowsOfSymbol` (`symbol-diff.ts`) cuts `highlightPatch`'s rows to `SymbolStatement.lines`, `{ base?, head? }` from each reader's `ReadSymbol.lines`, the range its text hash reads, so no symbol text goes on the wire, leaving out the lines of symbols strictly inside it, and a kept hunk's header is rewritten to where its rows start; a moved symbol shows both files through `otherEndOf`; the rows are `PatchRows` (`patch-rows.tsx`, Full diff's too), so a comment on one is a `lineAnchor` that shows in both). `tests-screen.tsx` is the Tests screen: All / For the selected node (`testsAlongside`, `src/core/tests-alongside.ts`, which Tested by uses too), the counts (`testCounts`), the files' trees (`DrawnFiles`, which Tested by uses too; on a served page each test takes a comment, its id the file and heading trail, counted from the second of one trail, whose draft in the tray goes to, and counts on, the node `nodeOfTests` names, the one whose Tested by shows the file) and the changed nodes, each going to Structure. On Logic only, offered when `nodesWithChangedLogic` holds a file, a file's node is a card (`logic-card.tsx`: `logicCardsOf` gives each its rows, a function with a changed decision each, and its size, which `layoutDiff(diff, { sizes })` lays out; `LogicCardBody` draws them in SVG, a tick going to its row through `Drawing.onTick`, inert in the reading map), findings, notes and said-in-place are placed with every box open (`boxesAllOpen`), and leaving it for a part it lacks goes to Changes only and wider (`scopesFrom`). `view.ts` holds the graph frame's zoom and pan rules (fit, zoom, pan, pin, centre, resize, all clamped), pure and tested in node. The CLI reads that file, never vite, so it must be built first: `pnpm build`, `pnpm review` and the tests' global setup (`vitest.setup.ts`) all build it.
- `src/test-support/` builds temporary git repos, Cargo workspaces and a fake `gh` for the tests. Pipeline rules are tested on `readStacks` with `fakeReader`/`fakeLinker` (`fakes.ts`); only what needs a real reader goes through `readRange` with the real adapters (`read-range.ts` there). `src/fixtures/` holds captured `cargo metadata` and depcruise output.
- `plugin/` is the Claude Code plugin (`plugin/skills/visual-review/SKILL.md` writes notes onto a page, on a later round with its answers to the last review, serves it in the background and acts on the review's verdict when `serve` exits), and `.claude-plugin/marketplace.json` makes the repo its marketplace (`pablocm90`). The skill runs the CLI through npx at the version `package.json` says (`plugin.test.ts` keeps `plugin.json` and the pin in step); `VISUAL_REVIEW_PACKAGE` swaps in another npm spec, such as a packed tarball's absolute path.

## Commands

- `pnpm install`, then `pnpm check` (biome), `pnpm typecheck` (tsc 7, no emit), `pnpm test` (vitest, ~40 s), `pnpm mutate` (Stryker), `pnpm build` (`dist/`: the CLI as JS via `tsconfig.build.json`, plus the page).
- The package is `@pablocm90/visual-review` with the bin `visual-review` (`dist/cli.js`), shipping only `dist/`. Anything the CLI imports at runtime must be in `dependencies`; what only the page bundles (React, ELK, highlight.js) stays in `devDependencies`. Check an install with `pnpm pack` and `pnpm add <tarball>` in a scratch project.
- **Pre-push gate:** `pnpm check && pnpm typecheck`. CI (`.github/workflows/ci.yml`, GitHub Actions on every push) runs those plus `pnpm test` and `pnpm build`, with git and cargo on the runner.
- `src/index.ts` is the package entry: types only (`Reader`, `Graph`…). Node ids are part of a reader's contract (JSDoc on `GraphNode`): notes are keyed by them.
- cargo runs inside the reviewed checkout (its `.cargo/config.toml` must apply) but with `RUSTUP_TOOLCHAIN` set to what rustup picks outside it, so the checkout's `rust-toolchain.toml` can't choose cargo. Before it runs, `refuseLeavingPaths` (`readers/rust/manifest-paths.ts`, smol-toml) walks the manifests cargo would read from the stack's `Cargo.toml`, following each named folder holding one, once by real path: every `path` value at any depth and `package.workspace` (or `project.workspace`), taken as written, and each `workspace.members` / `default-members` pattern, by its literal prefix, a `..` at or after its first glob refused, must resolve inside the checkout (the walk also starts at each folder above the root in the checkout holding a `Cargo.toml`, since cargo searches there for its workspace, and skips a glob match under `workspace.exclude` that no member holds; workspace keys of the wrong type are refused), and the cargo config of each folder from the checkout down to the stack's (the legacy `.cargo/config` when there is one, as cargo picks, else `.cargo/config.toml`) has every `include` (a string or `{ path }`, read from its `.cargo` folder, by real path, or by where it sits when missing, so an optional local override reads, an included file checked for its own, each once by real path, an `include` that is no list refused) resolve inside the checkout, and each file the walk reads must be a regular file, else the stack is not read (`StackNotRead`, naming the manifest or config and value); cargo then reads no stdin, is killed with SIGKILL after 60 s (`VISUAL_REVIEW_CARGO_MS`) and, on Linux, runs under a 2 GB address-space cap (`ulimit -v` through `/bin/sh`), each a stack not read too.

## Stack and gotchas

- Node 22.22 (`.tool-versions`) runs the `.ts` sources directly by type stripping: relative imports carry `.ts`, and no syntax that needs emit (enums, parameter properties).
- TypeScript strict with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `noPropertyAccessFromIndexSignature`: index results are `T | undefined`, and `process.env['X']` takes brackets.
- Biome: single quotes, width 100, arrow parens as needed; two a11y rules are off under `src/viewer/**`.
- TypeScript 7 has no JS compiler API, so dependency-cruiser parses TS through `@swc/core`. Without it the web graph silently reads no modules.
- The tests shell out to real `git` and `cargo`. `review-page.test.tsx` lays its fixture out once at load and waits up to 3 s (`asyncUtilTimeout`) in every `findBy` and `waitFor`, so a loaded machine renders the first page in time; ask before raising a timeout, and diagnose a flake with the test file run 12× in parallel under busy loops before blaming load. `vitest.config.ts` runs the `.test.ts` files first and the `.test.tsx` files after them, one at a time (`sequence.groupOrder`, `fileParallelism`), because a page test's slowdown follows the other files running during it: keep them apart. To expose a page test that reads before a relayout lands, delay `layoutDiff` by a temporary `setTimeout` and run the file at several delays; it should stay green.

## Conventions

- The domain's words (finding, dimension, level, fact, check, Start here) are defined in `GLOSSARY.md`.
- **This repo will be public.** Commit messages and PR bodies carry no `Claude-Session:` line, whatever the attribution reminder says. Keep `Co-Authored-By`.
- Changes land through PRs from a task branch (`claude-dev task <slug>`), never pushed straight to `main`.
- Publishing to npm and flipping the repo public are outward-facing steps the user runs or approves.
