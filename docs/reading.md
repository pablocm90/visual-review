# Reading a range

How `readRange` reads both sides of a range into a `RangeReading`: the readers, the config, the linkers and rules, the diff, and what is read per changed file.

Bare file names live in the folders [CLAUDE.md](../CLAUDE.md)'s layout names: `src/core/`, `src/readers/{rust,typescript,rails}/`, `src/linkers/`, `src/git/` and `src/viewer/`.

## Entry and readers

`src/cli.ts` is the entry point (`pnpm review <pr | from..to>`, or nothing for uncommitted work). `read-range.ts` checks out both sides of a range, drops each checkout's links that don't resolve inside it (`links-leaving.ts`: a link to a device or to `/proc/self/pagemap` never ends, and cargo and dependency-cruiser read files of their own, so no check per read would hold; `configAt` refuses a tracked config link leaving the repo and reads a working-tree config through `readFileThatEnds` (`src/core/file-that-ends.ts`: a regular file with a size, so `/dev/*` and procfs are refused and a link to a plain file outside the repo still applies), as `.reviews/` reads and a page's reads do), and reads each with `readStacks` (`read-stacks.ts`) through the readers in `src/readers/` (Rust: `crate-graph.ts`, `crate-modules.ts`, `rust-tests.ts`, `rust-measure.ts`, `rust-symbols.ts`; TS: `web-graph.ts` via dependency-cruiser, `typescript-tests.ts`, `typescript-measure.ts`; Rails: `rails-graph.ts`, `ruby-tests.ts`, `ruby-measure.ts`, parsing with tree-sitter-ruby in `ruby-syntax.ts`, no Ruby run; `parserOf` (`readers/tree-sitter.ts`) gives each grammar only `read` and `parsing`, which delete every tree they parse when the reading returns or throws, so what a reading returns holds no `Node`, and `trees-freed.test.ts` counts each reader's parses against its deletes), each implementing `Reader` (`reader.ts`): `roots` lists candidate roots, `holds` says whether one is its stack given that stack's settings, `graph` reads one stack under its drawn id, and it owns its test files, read only under a drawn root. `readStacks` owns the policy: naming, added and dropped stacks, labels, skips, linker stacks and edges with an undrawn end. It names roots in one pass, reader order then root order: a root's name (its own, else its directory, else the repo folder at `.`) gives a tentative id, the first free `~N` (`web~2`) when taken, and `holds` is asked with that id's settings; only a root that holds takes the id. A TS root is any directory with a `package.json` whose source root (tsconfig `rootDir`, else its one `include` folder, else `src/`, a folder leaving the checkout or absolute not counting) holds TS/JS sources, `node_modules` skipped; its stack id is the directory, or the package.json name (else the repo folder name) at the checkout root. A bare import of a sibling package's name joins the file to that stack, since checkouts have no `node_modules`. `typescript-config.ts` reads the tsconfig itself (jsonc-parser), not through `cruise`'s `tsConfig` option, whose plugin resolves `baseUrl` from `process.cwd()` and reads an `extends` wherever it points: `resolutionIn` gives `cruise` `paths` and `baseUrl` as its `alias` and `modules`, through relative `extends` (up to `MOST_CONFIGS`, each config read once), what leaves the checkout unsaid, an exact name passed with `$` so it matches only itself, and a name that would match file paths (`*`, `.`, `/`) not passed; a root holding no files (`files` or `include` said, both empty) with no `paths` in that chain takes the first referenced project's chain holding `paths` whole, and `references` are read from nowhere else; `rootDir` and `include` are still the stack's own tsconfig's, since following `extends` there would move node ids. An import resolving outside the checkout is `doNotFollow`ed and not drawn (`matchesDoNotFollow`), and one landing in a sibling stack's root draws the edge to that stack (`stackHolding`). `export type { … } from` and `export type * from` are missing from the cruise, so `withTypeReexports` (`typescript-type-reexports.ts`) parses a file holding one, under the size limit, and adds its dependencies to the cruise's output. A Rails root is any folder with `config/application.rb` outside `vendor/`, `node_modules/`, `test/` and `spec/`, named by its directory, or the repo folder name at the checkout root; its boxes are the `app/` folders holding Ruby (`app/lib` as `app/lib`) plus `lib/`, or the deepest folder matching a config box glob (`app/models/*` gives `models/billing`; a box doesn't change a class's constant), and its nodes are classes keyed by constant (`<stack>/class/Admin::UsersController`), read from the file's `class`/`module` definition naming the longest tail of its path. Its edges are the constants a class writes, resolved through Ruby's lexical scope, and its model associations, resolved from the owner's constant as ActiveRecord does (`class_name:`, `source_type:`, `source:`, else the name, singularized for `has_many`, matched ignoring case). Its test files are `*_test.rb` under a `test/` folder and `*_spec.rb` under a `spec/` folder, read by one walker (`ruby-tests.ts`): `test "…"` calls and `test_` methods under a heading per class constant, and `it` / `specify` / `example` / `scenario` (an `it { … }` named by its block) and `it_behaves_like` (named by its arguments) under a heading per `describe` / `context` / `feature`, named as RSpec names groups; a test word on a receiver is no test, and shared and `x`/`f` groups aren't read.

## Config

`config.ts` validates `visual-review.config.json` (Zod, `strictObject`), read from the head revision or else the working tree, and applies to both sides: readers get a stack's settings in `holds` and `graph` (box globs, `sourceRoot`), stacks added with `reader`+`root` keep their key as id, relabelling happens in `readStacks` on drawn ids, and a dropped (`false`) stack's graph is never read. Its `notes` and `security` entries alone are read from the range's base instead, from the tracked file only and checking nothing else there, a file that isn't JSON reading as their defaults (`baseConfigAt` in `read-range.ts`, `parseBaseConfig`), so a change can't guide its own review or open its own actions: `RangeReading.notesConfig` (`guidance`, and the `why` and `recommendation` switches, off only when `false`), `{}` with none, carried as `PageData.notesConfig` for the skill, which follows its `guidance` within the notes format and leaves a switched-off field out; the page doesn't read it, and `--notes` refuses a note carrying a switched-off field (`notesProblems`: `<field> is switched off on <key>`).

## A reader whose tool is missing

A reader may name the command its `graph` runs (`Reader.tool`, `cargo` for Rust): when it isn't on `PATH` (`on-path.ts`, a lookup, nothing run), none of its stacks is read and the review lists its kept stacks as `skipped` (`skipped.ts`), as it does a stack whose `graph` throws `StackNotRead` (any other throw fails the run), each entry by reader and reason, its finding by its stacks and side; `readRange` drops a stack not read at either side from both graphs before the diff, its entry naming the `side` when the other side read it, and drops those and the stacks not read at the last review's head or fork from the since-review graphs, the reviewed reading carrying its own head graph (`after`), listing those last ones, by reader and reason, at `side: 'reviewed'` ("at the last review"); shown on stderr and as the alert atop the page's findings rail; its test files are still read. The CLI looks up `git`, and `gh` for a PR number, the same way and exits 1 naming the one missing, and refuses a root with no `.git` entry (`repoRoot`). What it and serve write under `.reviews/` goes through `writeAnew` (`src/write-anew.ts`): a temporary file renamed over the path, so a link there is replaced, overlapping writers all succeed, and a regular file's mode is kept. It finds the repo root under `safe.bareRepository=explicit`, so a folder a branch lays out as a bare repository is never taken for the repo, and every later git call runs from that root. Each `Reader` names itself and the stack fields it takes (`stackFields`). Naming problems (an added root detected as another stack, an added key detected elsewhere or drawn by another reader) fail before any graph is read; the rest (undetected, field not taken, unlinkable: `checkConfig`) once both sides are read. `pnpm build` writes `dist/config.schema.json`, `dist/notes.schema.json` and `dist/review.schema.json` from their Zod schemas (`write-schemas.ts`).

## Linkers

Linkers (`Linker`, `linker.ts`) then draw edges across stacks from the drawn nodes: `linkers/fetch-axum/linker.ts` reads the fetch calls of every TS stack's files and the `.route("…")` paths in the module files (the files its targets reach, not `tests/` or nested crates) of every crate whose `Cargo.toml` depends on axum (`api-paths.ts` parses both), and lists unrouted calls as dangling; with no axum crate it draws nothing and says so (`Links.notRead`, optional on the exported `Linker` contract), which coverage leaves out where a Rails app's routes are read. The config's `linkers` entry turns one off or names its `from`/`to` stacks.

## Rules

The config's `rules`, keyed by name, each `{ from, notTo, reason }` by node id glob, are read over the head graph by `ruleBreaks` (`rule-breaks.ts`, `matchesGlob` from `node:path`, so Node side only): an edge breaks one when its start matches `from` and its end `notTo`, each by itself or a node holding it, unless its start matches `notTo` too, and an empty glob list is refused at parse; `rule-findings.ts` raises `rules:broken:<name>:<edge id>` on the edge, `look` when the diff adds it and `info` when unchanged, and `rulesNotRead` gives the rules coverage (`none configured`, or each glob matching no node at the head).

## Tests

`test-changes.ts` compares a test file's tests across the sides, tests of one name paired in order, a heading whose label changed editing the tests under it, and `anchoredTests` gives each its trail, counted from the second of one trail in the file; each test file carries its stack's id (`stack`, from the deepest root of its reader holding it), since every reader draws its stack node at path `''`, which holds no path.

## The diff

`diff-graphs.ts` diffs the sides, matching edges by `edgeId` (`graph.ts`, the `<from> -> <to>` notes use too). `visible-diff.ts` draws a node inside closed boxes as the outermost of them, at any depth.

## Churn and metrics

`read-range.ts` also counts each side's churn per drawn file (`git log` over `metrics.churnDays` days before that side's committer date; uncommitted work's head counts up to `HEAD`), and `metrics.ts` puts it on the changed nodes plus one hop of the diff's edges, with fan-in/out and, from the reader's optional `measure` (Rust: `rust-measure.ts`; TS: `typescript-measure.ts` over Babel's AST; Rails: `ruby-measure.ts` over tree-sitter-ruby; TS and Rails test files measured as `undefined`, which leaves a file unmeasured), lines, functions, cyclomatic (its highest, its total and each function's, `cyclomatic.byFunction`, a Rust function's `?`s counted apart as its `earlyReturns`) and ABC; a box takes the highest of each measured inside it (`highestInside`).

## Symbols and logic

For each changed file `read-range.ts` also reads both sides' symbols through the reader's optional `symbols` (TS: `typescript-symbols.ts`, over the Babel parse and walk it shares with `typescript-measure.ts` in `typescript-syntax.ts`; test files and non-script files read none, and a parse error is kept as `unreadable`; each function's and method's decisions, its guards, ifs, ternaries, loops, cases, outermost logicals, catches, returns inside a branch and throws, are read by `typescript-decisions.ts` as normalised source text with their depth and line; Rails: `ruby-symbols.ts`, over tree-sitter-ruby, test files reading none and a parse error or a file over the limit in `too-big.ts` kept as `unreadable`: a class or module by its full constant, not exported when a module holding only definitions, its methods, setters, attrs, delegates and scopes under it, visibility walked in order per body, and what a class holds cut from its hashes as holes, an attr or delegate call only when its symbols read all of it, so an edit inside reads there alone; `ruby-decisions.ts` reads the decisions of a method or scope, and of a class its callbacks, validations and `rescue_from`, those found by name marked `foundByName`, and lists the calls that hide logic as `FileSymbols.blindSpots`, raising `logic:blind-spot:<node>` for information, which alone raises no `tests:untested-logic`; `ruby-risks.ts` reads a method's or scope's risky calls by name as `ReadSymbol.risks` (`Risk`: `permit` per key, symbol or string, in a braced hash or not, nested as `address.street`, `permit!`, `raw-sql`, its `detail` saying whether the string is interpolated, a heredoc read from its body, the one after its beginning, counting those begun before it on its line, and a call on a string (`.squish`) as that string, `html-safe` and `dynamic-send`, a `send`, `public_send`, `constantize` or `safe_constantize` of no literal), which `symbol-changes.ts` keeps as `SymbolStatement.risks`, the head's over the paired base symbol's as a multiset by kind and text, all of an added one's and none of one moved whole, and `security-findings.ts` raises `security:<kind>:<symbol id>#<text>` to look at on the file's node, the same text twice counted (`countingRepeats`, `counted-id.ts`, as `decisionsOf` keys decisions, so an answer stays on its call when another is gained above it), and, over every patch, `security:html-safe:<path>#<code>` on each line an `.erb`, `.haml` or `.slim` view gains holding `html_safe` (not `html_safe?`), `raw(` or `<%==`, by `Finding.file` and `Finding.line`, since views aren't parsed; an argument `permit` can't name (`*FIELDS`, `FIELDS`, `**OPTIONS`) is a `Risk` marked `unread`, raising no finding, which the security coverage lists by node and method; the security coverage names each other reader (`risky calls not read for <reader>`) and each changed file whose symbols weren't read, or, with no Rails reader and no controller read, `authorization and risky calls: Rails only`; `secret-findings.ts` raises `security:secret:<path>#<format>` over every patch, drawn or not, on each added row holding a known key format or, outside lockfiles and only when no format matched, a value of entropy over 3.5 and 16 characters or more assigned under a secret-like name, and `#secret-file` for a secret file the change adds, `info` in a test file or fixture; `pageData` (`page.ts`) masks each value `secretValues` gives (every match on a row, a private key's base64 body lines, also inside one row's `\n`s, and, in an added secret file, each row's variable value or else the row, of 8 characters or more) in every string and object key of the page data, longest first, as `masked` shows it, so a planted value shaped like one masks matching text elsewhere, still reading as a mask; Rust: `rust-symbols.ts`, over tree-sitter-rust, sharing `hashesOf` and `shapeOf` with Ruby through `readers/tree-sitter.ts`, off `.rs` or under a `tests/` segment reading none and a parse error or a file over the limit kept as `unreadable`: a `fn`, an `impl`'s methods scoped by the type without generics, an `impl Trait for`'s by `Foo as Trait<A>`, exported when the type is `pub` in the file, a trait's by the trait, and a struct, enum, union, trait or type alias as `type`, exported only when exactly `pub`, a struct's signature holding only its `pub` fields and a trait's no default bodies; an inline `mod`'s are walked, named `inner::z` or scoped `inner::Foo`, exported only if every `mod` around is `pub`; `exports` adds `pub` consts, statics, mods and `pub use` names; `#[test]` and `#[cfg(test)]` items read nothing but stay in `astHash`; `rust-decisions.ts` reads a function's decisions: `ensure!`, the asserts, `bail!`, `panic!` and the like only by name, marked `foundByName`, a `?` as the kind `try`, inner ones first, its text leaving out closure bodies, blocks and the `?`s inside it, whose logic reads as lines of its own, a nested `fn` reading none, and lists as `FileSymbols.blindSpots` the other macros and the `macro_rules!` holding a `return` or `if` token or a `?` that isn't a sigil or a repetition's, outside test code), lists as `symbolsNotRead` the stacks with changed files whose reader has none, and `symbol-changes.ts` pairs the symbols across the sides (scope, name and kind, a method and an accessor pairing across those two kinds when neither has an exact partner; formatting by text hash; renames by body hash, or "probably" by token similarity; moves between changed files), diffs the export names, gives the file its kind of change, `api`, `logic` or `formatting`, and gives an edited or renamed symbol whose decisions differ its `logic` lines, and an added symbol all of its decisions as added ones (counted, drawn and asking for a test, but raising no `logic:changed`; a Rails class macro's subject is its name and the positional arguments that name something, not a lambda or call, so one replaced in place reads as lost and added, and an edit to its options or a name added as changed), the pairing carrying each statement's read symbol, so a repeated name goes by its own, and across all the files a removed line whose kind and text another symbol gained (a new symbol's decisions, or an edited one's added lines; ## Reaches

For each changed file `readReaches` (`read-reaches.ts`, called from the head reading only, so a later round's reviewed side reads none) asks the reader's optional `uses` (TS: `typescript-uses.ts`, by name over the Babel parse, its candidates the base graph's edges into the file, since at the head a removed file has none, barrels followed, what it can't follow a row marked `unfollowed`, a candidate named through an alias found by `placesNamedBy`, from the importer's own root in `UsesAsked.stacks`, the asked reader's stacks only, a sibling's import of the package's name counting, a default through it only marked, each stack's script files with no node at either side (`UsesAsked.graph`, `graphAtHead`) joining every target's importers (`typescript-outside.ts`, none past `MOST_OUTSIDE_FILES` per stack, a folder with its own `package.json` or another stack's root not its own), what is still unseen a line in `notFollowed`, as is the count of those files it couldn't read, a drawn file going by path in `notRead`, only a file not there reading as no file, and each read synchronous, since one at a time keeps a big repo's descriptors and reads through the threadpool in turn stall on a busy machine; Rails: `ruby-uses.ts`, over tree-sitter-ruby, its candidates the classes with an edge into the changed class that name the owner by `namingsIn`, a method at the first receiver call, `&:x`, or symbol or string sent or delegated (`delegate`, `def_delegator`, `def_delegators`), any receiver but `self` counting, a `send` or `delegate` of a name it can't read (not a literal, a `%` form, an escape) a row marked `unfollowed`, a file too big or not parsing in `notRead`, each file's tree freed once read, since the parser hangs after enough unfreed big ones; Rust: `rust-uses.ts`, over tree-sitter-rust, its candidates the modules with an edge into the changed one and every module of a crate with an edge into its crate, reading `use` paths through `use-paths.ts`, the walker `crate-modules.ts` draws its edges with, each keeping its own start (`crate`, `self`, `super`, a 2018 relative path, the asked crate's name), a written path also taking the asked crate's name, `crate`, `self` and `super` as in scope, a type or function at its first path naming it, a method by its type's path or at the first `.name` in a file importing its type, a row in a `tests/` folder or `#[test]`/`#[cfg(test)]` item marked by `SymbolUse.test`, which `readReaches` takes over the reader's `isTestFile` (every `.rs` file), a file too big or not parsing in `notRead`, one gone at the head no use, and what it can't see always a line in `notFollowed`) about each exported symbol removed, renamed, moved away, no longer exported or with a changed signature, a method by its qualified name (`Foo.bar`, the reader's row a file naming the class and reading `.bar`), and each removed export name no symbol backs, drops uses in changed paths, and gives `RangeReading.reaches` and `reachesNotRead`, the finished lines coverage shows, a `uses` that throws among them; `reach-findings.ts` raises `blast-radius:reaches`, and `Reaches` (`reaches.tsx`) lists them in the column after Tested by, its findings above their rows and out of Why look.

## Running cargo

cargo runs inside the reviewed checkout (its `.cargo/config.toml` must apply) but with `RUSTUP_TOOLCHAIN` set to what rustup picks outside it, so the checkout's `rust-toolchain.toml` can't choose cargo. Before it runs, `refuseLeavingPaths` (`readers/rust/manifest-paths.ts`, smol-toml) walks the manifests cargo would read from the stack's `Cargo.toml`, following each named folder holding one, once by real path: every `path` value at any depth and `package.workspace` (or `project.workspace`), taken as written, and each `workspace.members` / `default-members` pattern, by its literal prefix, a `..` at or after its first glob refused, must resolve inside the checkout (the walk also starts at each folder above the root in the checkout holding a `Cargo.toml`, since cargo searches there for its workspace, and skips a glob match under `workspace.exclude` that no member holds; workspace keys of the wrong type are refused), and the cargo config of each folder from the checkout down to the stack's (the legacy `.cargo/config` when there is one, as cargo picks, else `.cargo/config.toml`) has every `include` (a string or `{ path }`, read from its `.cargo` folder, by real path, or by where it sits when missing, so an optional local override reads, an included file checked for its own, each once by real path, an `include` that is no list refused) resolve inside the checkout, and each file the walk reads must be a regular file, else the stack is not read (`StackNotRead`, naming the manifest or config and value); cargo then reads no stdin, is killed with SIGKILL after 60 s (`VISUAL_REVIEW_CARGO_MS`) and, on Linux, runs under a 2 GB address-space cap (`ulimit -v` through `/bin/sh`), each a stack not read too.
