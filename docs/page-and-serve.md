# Page data and serve

The reading order, the page data contract in `page.ts`, and `serve`, which takes the review back.

Bare file names live in the folders [CLAUDE.md](../CLAUDE.md)'s layout names: `src/core/`, `src/readers/{rust,typescript,rails}/`, `src/linkers/`, `src/git/` and `src/viewer/`.

## Reading order

`reading-order.ts` orders the parts (changed nodes with no changed node inside) by the head graph's edges, depended-upon first, a part reaching through its boxes' edges too; parts that reach each other are one cycle, read in id order, and removed parts come last: `PageData.readingOrder`, where `page.ts` moves each test file to just after the part it tests (`testsAfterSubjects`, `subjectsOfTests` in `tests-alongside.ts`: named alike in its stack, neither in a cycle), listed atop the left column (`reading-order-list.tsx`, each part named by `partLabels`, its boxes' names before it while another part reads the same: `graph › lib.rs`), each changed test file with no node of its own (a crate's `tests/` file, a Rails test) listed unnumbered under the last part whose Tested by holds it (`testsWithoutNodes`, by its path in its box, `testPathIn`), going to that part with the files outside the graph after it, and numbered on the drawn parts. On the page `J`/`K` walk the parts (a document key listener in `review-page.tsx`, on while Structure is shown, any case, ignored in textareas and with Ctrl, Meta or Alt), entering reading, a state of `Page` (`reading`) that `walkTo` also sets, for the head's Next, a reading order row and Start reading, while a click in the graph, a finding and Start here keep the graph whole. `L`, and the head's Next logic change, walk the changed decisions across files (`walkOfDecisions` and `nextDecision` in `src/core/logic-strip.ts`: reading order's parts first, then each file's symbols and logic lines in order), from the row landed on, else the selected part's first, else the first, entering reading and landing through `goToRow` with focus on the row, so `C` comments on it; past the last there is none, so the button hides and `L` stays, as Next does at the last part. While reading, `.columns` renders `ReadingStops`, then the column and the aside keyed `[side, content]`, so the frame and inspector keep their state and no second ELK runs; the graph is the map (`useGraphView(layout, map, current)`, `mapHeight`, `aroundPart` and `ringAround` in `view.ts`: centred on the part's neighbourhood, with no zoom, pan, wheel, keys or toggles, nodes at `tabIndex` -1, `aria-current` and a ring on the part, a click going to it), and the aside holds Next to it (`next-to-it.tsx`, from the diff's own edges, the unchanged ones to unchanged nodes folded) and All findings; `ReadingStops` names each stop, a test file's indented. Open map, Escape outside a field and the column's `×` leave reading. `scrollInPanel` (`scroll-in-panel.ts`) puts the window back after a row's `scrollIntoView`, then lifts a landed row (`center`) clear of the tray or back into the window; `ReadingProgress` counts the parts read in the header. `A` marks the selected part read; the marks are kept in `localStorage` by range (`read-marks.ts`, Zod-parsed, every access in a try), so they last a reload but not a new serve, whose port, and so origin, is new; the review sends those on the reading order's parts, and the review tray counts them.

## The page contract

`page.ts` is the page's contract: it builds the page data from a range reading (its types in `reading.ts`, so the page and the checks take a reading without the I/O of `read-range.ts`) (every field present, stamped with the CLI's version), puts data and notes into `viewer.html`'s slots and reads them back (`main.tsx` reads them through it, so it imports nothing from `node:`, which `bundle-boundary.test.ts` checks by walking every runtime import from `main.tsx`), and on `--notes` checks the notes against the data inside the page and refuses a page another version wrote. The CLI only does I/O around it; the `.json` beside the page is for readers such as the skill.

## Serve

`pnpm review serve [--no-open] <page.html>` (`src/serve.ts`) serves a written page, opening it unless `--no-open`: node:http on `127.0.0.1` port 0, the page at `/<token>` (a random token per serve, filled into the page's `review-serve` slot by `page.ts`'s `servedPageHtml`), the review POSTed to `/<token>/review`, any other path or `Host` 403. A body `parseReview` (`src/core/review.ts`, Zod, `dist/review.schema.json`: a `verdict`, `approve` | `comment` | `request-changes`, an optional general comment `body`, `reviewed`, the range and PR number the page was drawn for, `read`, the reading order's parts marked read, `resolved`, the anchors of the last review's comments and answers closed, as they were said, and `comments`, one per anchor: a comment on a part or edge, or an answer to a finding by its id) accepts is written as `<name>.review.json`, answered 204, its path printed, and serve exits 0; one it refuses gets 400 with the parse error and serve keeps serving. `main.tsx` reads the token through `pageIn` and hands `ReviewPage` a `send` that POSTs with `sendReview` (`page.ts`, which the serve tests call too, so they send what the page sends); with no token there's no `send`, and the page shows no comment field and no review tray (`review-tray.tsx`, a bar at the page's foot: closed, it counts the drafts by kind; open, it lists them, comments in reading order, then finding answers by their finding's title, each going to its anchor (a diff line's at its row, in Full diff or, when no node holds its file, in the files outside the graph) or the finding's target, and the parts read with nothing to say, and holds the general comment, the verdict, suggested from the drafts until one is picked, Send, and What Claude gets, the review as lines). `main.tsx` also pings `/<token>/ping` (`pingServe`) on load and every 30 s; serve waits for the first ping up to 24 h (`VISUAL_REVIEW_FIRST_PING_MS`), then each ping refreshes its idle timer (10 min, `VISUAL_REVIEW_IDLE_MS`); when either ends, serve exits 1 with "No review sent". Serve's lock, `~/.cache/visual-review/serve/<sha256 of the page's real path>.json` (`{ pid, port, token }`, mode 600, Zod-checked), outside the repo so that no checked-out file can be taken for it (a umask of 077 checks every file out as mode 600, so no mode can tell them apart), makes a second serve of a live page open its URL (print it on stderr under `--no-open`) and exit 0 with nothing on stdout; a lock whose server doesn't answer `POST /<token>/alive` (a check apart from the page's ping, so it never starts the idle count), or that doesn't parse, is replaced, and serve removes its own on exit, on a signal too. A home that isn't absolute, or a lock it can't write, exits 1 naming the lock.
