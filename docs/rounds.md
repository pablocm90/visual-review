# Later rounds

How a PR's later round reads its last review: the reviewed head, what changed since, and the last review's comments on the page.

Bare file names live in the folders [CLAUDE.md](../CLAUDE.md)'s layout names: `src/core/`, `src/readers/{rust,typescript,rails}/`, `src/linkers/`, `src/git/` and `src/viewer/`.

## The last review

For a PR number `cli.ts` asks `lastReviewOf` (`src/git/last-review.ts`) for the newest `.reviews/*.review.json` of that PR at another head, read through `pastReviewOf` (`review.ts`), which needs only `verdict` and `reviewed` and keeps what it can of `body`, `read` and `comments`, comment by comment, so an older format's review still counts, and `lastReviewOf` adds `calledFine`, the findings whose newest answer over all the PR's reviews is `fine`; a file git tracks came with the repo, so neither it nor pruning counts it (`git ls-files --others`, run from the repo root: inside `.reviews/` a branch could lay out a bare repository git would use, whose config runs commands), the head must be a full SHA, and it's compared with the new head as a commit, so a tag object of that head is that head; `readRange` reads that head as a side of its own, the reading's `reviewed`, with the PR's own diff at that head as `pullRequest` (from `merge-base(from, head)`, reusing the range's base graph when that's the same commit, else one more side) (or `gone` when the commit doesn't resolve, a force-pushed head still in local objects still reading, or `unreadable` with the message when reading it fails, which doesn't stop the review), and `sinceReviewOf` (`since-review.ts`) diffs it against the head, counting only paths the PR changes at either head and keeping only the nodes and edges it changes at either, so a merge of `main` counts only where it touches one of its paths: `PageData.sinceReview`, with `changed` Show's Since last review (`sinceLastReview`; a part the PR has restored stays in `nodes` or `edges`, drawn as unchanged, its edge kept apart from the merge like a noted one while this choice is picked, a reviewed id going by the head's name when renamed since, and what the head doesn't hold goes in `dropped`, named by a line under Show), and without it a header line saying the full review is shown. `changed` also lists `symbols`, `decisions` and `tests`, by the ids their comments anchor to, and `files`: the reading holds each pair's symbols and tests too, a symbol or test kept when the PR changes it at the head or, by its former id, at the reviewed head; the page marks them "changed since" on any later round, whatever Show holds, through `ChangedSinceMarks` (`changed-since.tsx`), a context read by the symbol rows, logic lines, test lines and `Patch`, a diff line counting by its file. `sinceReview`'s every variant also carries the last review's `verdict`, `body`, `calledFine` and `comments`, each given by `previous-comments.ts` its `target` at the head and, when compared, `changedSince`, the commits touching its file (the reading's `commits`, one `git log -z` of `reviewed..to`), absent for "As it was"; the compared variant adds `changedWithoutComment` and `stillRead`, the start `storedReadMarks` takes when nothing is stored for the range. On the page `LastReview` (`last-review.tsx`) lists them atop the left column, and `SaidBefore` (`said-before.tsx`, context `LastSaidOnPage`) shows one under its anchor: the reading column (an edge's also on the arrow drawn in its place, `edgesSaidInPlace`), symbol rows, logic lines, test lines, patch rows, the rail's findings, not Start here, which leaves out what's `calledFine`. On a served page `Said` offers `Resolve` (not on a `fine`), held in `Page` and sent as said in the review's `resolved`, counted and listed by the tray and named in What Claude gets, and `Reply` (not on a finding answer), a `CommentOpener` on the anchor at the head, so `CommentOn` and an edge's field step aside where `useHasSaid` holds; `RespondingOnPage` provides them inside `Page`, since `LastSaidOnPage` wraps it. The drafts themselves reach every field through one context, `Drafting` (`comment-field.tsx`: `comments` and `onComment`, undefined on a page that isn't served), provided once by `Page` with `ChangedSinceMarks`, so no component passes them down: `CommentOn`, `CommentField` and `CommentOpener` take only their anchor and show nothing without `onComment`, and what asks whether a row holds a draft reads `useDrafting()`. `anchorTarget` answers for the head: what it lacks has no target, so its draft is named with nowhere to go. `Said`, which both render, shows Claude's answer under its comment, by the anchor as said; `LastReview` also lists the notes' `unasked`. `pruneReviews` keeps each PR's newest review past its page.
