# Change readers

The ports `readChanges` (`read-changes.ts`) runs over the changed files alone, with no drawn stack: lockfiles, migrations, schema dumps, routes and authorization.

Bare file names live in the folders [CLAUDE.md](../CLAUDE.md)'s layout names: `src/core/`, `src/readers/{rust,typescript,rails}/`, `src/linkers/`, `src/git/` and `src/viewer/`.

## Lockfiles

A lockfile changed in the range becomes `PageData.dependencyChanges`, read by `readLockfiles` (`read-lockfiles.ts`, one of the change readers `readChanges` (`read-changes.ts`) runs from `readRange`, `ChangeReaders` beside `Adapters`, since `readStacks` never uses them; `adapters.ts` exports both as one `adapters` bundle, the one place an adapter is added) through each `Lockfile` port (`lockfile.ts`) in `src/lockfiles/{pnpm,npm,yarn,cargo,bundler}.ts`, listed in `adapters.ts`; they aren't `Reader` methods because a lockfile needs no drawn stack, a gem no Rails root. `git show` reads each side's text at its commit, so a symlink reads as its link text, and `\r\n` is normalised once there. Lockfiles of one ecosystem in one folder that changed together are read as one, so moving package manager raises only what moved, and a rename goes by its last path. A reader fails closed: any line its tool wouldn't have written throws, which raises "not read" naming only the format, since a quieter reading could hide a package. `yarn.lock` alone takes `Lockfile.manifest`, each side's `package.json` files under its folder. `packageChanges` (`dependency-changes.ts`) pairs the sides by compatibility line, and `dependency-findings.ts` raises the findings, each with `Finding.file`, which the rail, Start here and the tray open through `showFile` in `review-page.tsx`: the node holding the file in its Full diff, else the files outside the graph, landing at the patch's top.

## Migrations

A Rails migration the range adds becomes `PageData.migrations`, read by `readMigrations` (`read-migrations.ts`, a `readRange` option beside `lockfiles`) through each `MigrationReader` port (`migration.ts`), so no drawn stack is needed and `Reader` stays as it is. `railsMigrations` (`readers/rails/migration-risks.ts`, listed in `adapters.ts`) holds the paths Rails would run and gives each risk's title, why and line, reading every call except under `def down`, `def self.down` and a `down` block; a table the file creates raises no index or `null: false` risk, a reference indexes unless its `index:` is `false`, `nil` or concurrent, a `change_table` column only with `index:` (`add_column` takes none: ActiveRecord refuses the key), and a file that doesn't parse throws, kept as `notRead`. A path counts when it's absent at the base, so a rename counts and an edit doesn't, unless it moves a migration with its version kept (`MigrationReader.version`): that one has already run. `migration-findings.ts` raises one `schema` finding to look at per risk, with `Finding.file`, so the page opens it through `showFile` as it does a lockfile; only `schema:not-read:` is a blind spot in Start here.

## Schema dumps

A schema dump the range changes becomes `PageData.schemas`, read by `readSchemas` (`read-schemas.ts`, a `readRange` option beside `migrations`) through each `SchemaReader` port (`schema.ts`), so no drawn stack is needed. `railsSchema` (`readers/rails/schema-tables.ts`, listed in `adapters.ts`) holds `db/schema.rb` and `db/<name>_schema.rb` outside `NOT_SEARCHED` and reads each `create_table`, a column being any `t.<word>` that isn't an index or a constraint, every option kept as one as-written string; a file that doesn't parse throws, kept as `notRead`, and a dump absent at one side reads as `whole`, with its table count, so moving to `structure.sql` raises no table. `diffTables` (`schema-diff.ts`) pairs tables, columns and indexes by name, and `schema-findings.ts` raises the findings, each with `Finding.file` and, when it's about one table, `Finding.table`. `showFile` sends a file in `review.schemas` to the Schema tab (`schema-screen.tsx`, `SchemaLanding` focusing the card or the file's section); the tab is absent, and `#schema` falls back to Structure, with no schema change. `readChanges` also reads, for the deploy findings, the head's files naming a removed column (`columnsNamedAtHead`, `namedAt`: one `git grep -F -w -o -z` at the head, each path and name once, less a file whose own `ignored_columns` at the head lists that name) and the columns the base's models ignore (`columnsIgnoredAtBase`, `ignoredAt`: the `.rb` files naming `ignored_columns`, listed by `git grep -l -z`, each given to `SchemaReader.ignored`). Neither is read when the range removes no column. `railsSchema`'s `ignored` reads `ignored_columns =` and `+=` (strings, symbols, `%w[]`), on the table `self.table_name` names, else the plural of the file's name.

## Routes

A route change becomes `PageData.routes`, read by `readRoutes` (`read-routes.ts`, a `readRange` option beside `schemas`) through each `RouteReader` port (`routes.ts`), since a route file can't be read alone: `load` and `draw` join them, and `draw` under a `namespace` takes its prefix. When a held path changed, both sides' held files come through one `git cat-file --batch` each, so an unchanged file a renamed namespace reaches still counts. `railsRoutes` (`readers/rails/route-reader.ts`, listed in `adapters.ts`) expands them over tree-sitter-ruby with `inflection.ts`, ActiveSupport's table, which `rails-graph.ts` shares; a root is a `config/routes.rb`, a file nothing reaches isn't read as routes, and what it can't expand without guessing is `unread`, by source text and line, with what sits under it. A reading stops at `MOST_SPENT`, since repeated draws and nested names multiply, and that or a parse error throws, kept as `notRead`: its `file` is the changed file a `RouteFileNotRead` (a parse error or too big) names, else, as for that limit or an unchanged file, the first that changed. `diffRoutes` (`route-diff.ts`) keys routes by root, verb and path, the first drawn answering, and compares `unread` as a multiset by root, path, module and text. `route-lines.ts` reads PATCH and PUT of one path and target as one line, and `route-findings.ts` raises the `routes` findings, each with `Finding.file`, the row's `patch`, and, for one route or statement not read, `Finding.route`, its key in `route-lines.ts` (`lineKey`, `keyedStatements`, the text counted); only `routes:not-read` is a blind spot in Start here. `showFile` sends a `patch` the reading holds to the Routes tab (`routes-screen.tsx`, `RoutesLanding` focusing the row, the statement or the file's section), the rail and the tray passing the finding's `route` as its place; each file's section has `Show patch`, through `showPatch`, the part of `showFile` that opens a file's patch on its holder's Full diff or in the files outside the graph; its rows share `change-row.tsx` with Schema, and the tab is absent, `#routes` falling back to Structure, with no route change.

## Authorization

A controller action's authorization becomes `RangeReading.access`, read by `readAccess` (`read-access.ts`, a `readRange` option beside `routes`) through each `AccessReader` port (`access.ts`), holding `app/controllers/**/*.rb` outside `NOT_SEARCHED`, concerns included: when a held file changes, or the range adds or changes a route, both sides' held files are read whole (`filesHeldAt`, `git.ts`, which `readRoutes` shares). `railsAccess` (`readers/rails/access-reader.ts`, listed in `adapters.ts`) reads each file's public instance methods as actions, by `Controller#action` and the path Rails routes it by, and covers one when, walking its superclasses within its app (looked up as `rails-graph.ts` resolves constants) and its concerns' `included do` callbacks, an authorizing `before_action` or `around_action` (prepend and append forms too), or an `after_action` naming `verify_authorized` (`AFTER_THE_ACTION`: any other runs once the action has), reaches it under its `only` / `except` and no later skip removes it, or when its own body calls an authorizing name; a cover under `if:` / `unless:` is `conditional`, and an unconditional one wins. The names are `security.authorize`, `*` a wildcard (`wildcard.ts`), Pundit's and CanCanCan's by default. What the walk can't read (a callback list with a splat, a block calling no authorizing name, a parent or concern outside the controllers read) is the action's `unread`, each row by its first line, and a file that doesn't parse or is too big is its table's `notRead`, the others still read. `access-findings.ts` raises `security:unauthorized:<root>:<Controller#action>` on the controller's node, else by `Finding.file`: `look` for a head action with no cover that is new, lost its cover, or is reached by a route the change adds or repoints, `info` for the same with only a conditional cover, or one gone from always to conditional; an existing uncovered action raises nothing, nor does one a `security.open` glob (`Controller#action`) matches. `accessNotRead` gives the security coverage: the controllers not read (at the base only when the head read it), the unread rows of the actions that could raise, once each, and each `open` glob matching no action at the head; `Rails only` with no controller read and no Rails reader. The config's `security` is read from the range's base with `notes`, so a change can't open its own actions.
